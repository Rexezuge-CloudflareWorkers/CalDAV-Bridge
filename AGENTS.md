# AGENTS.md

Guidance for agents working in CalDAV Bridge.

## Overview

CalDAV Bridge is a Cloudflare Worker API with a Vite React management UI. It connects Google Calendar and Microsoft Outlook Calendar over OAuth2 and exposes them through read/write CalDAV endpoints.

## Commands

Always source the user's toolchain setup before Node, pnpm, npm, npx, or Wrangler commands:

```bash
source ~/.customrc
volta run pnpm install
volta run pnpm run typecheck
volta run pnpm run test
volta run pnpm run test:integration
volta run pnpm run build
volta run pnpm run typegen
```

## Architecture

**API app** (`apps/api/`):

- `src/index.ts` — exports the default `fetch`/`scheduled` handlers via `CalDavBridgeWorker`; re-exports `CronTasksWorker` from `@caldav-bridge/background` for the DO binding (`OAuth2TokenRefreshWorker` was removed; see below).
- `src/workers/CalDavBridgeWorker.ts` — thin Hono router (extends the kit's `AbstractEntrypointWorker`): registers `/user/*`, `/api/oauth2/callback/:applicationId`, `/dav/*`, and the SPA fallback; all handler logic lives in `@caldav-bridge/backend-services`. DAV XML dispatch stays here; only pure CalDAV helpers live in services.
- `src/middleware/` — `MiddlewareHandlers.userAuthentication()` (Cloudflare Access via the kit's `authenticateAccess` from `@rexezuge/http` + `UserService.upsertUser`), setting `AuthenticatedUser` to the resolved `ResolvedAccount` and mapping client errors to `{ error }` JSON (the kit's Access refusal is a 401 `ServiceError`, so there is no local translation). `DEV_AUTH_EMAIL` bypasses Access locally through the kit's `bypassAllowed`/`devAuthEmail` options; it is read structurally (`AccessEnv`) because the var is deliberately absent from the wrangler template, so a deploy can never enable the bypass.
- `src/generated/spa-shell.ts` — generated by web build; do not edit.

**Background app** (`apps/background/`):

- `CronTasksWorker.ts` — DO serializing cron runs (`POST /run`, `already_running` dedupe) → `DatabaseCleanupTask`; a failed run answers 500 `{ status: 'failed' }` (the kit's `AbstractScheduledTask` rethrows task failures since 1.8.0, so that path is reachable). `OAuth2TokenRefreshWorker` was removed (unauthenticated token dispenser; refresh happens inline in `OAuth2AccessTokenService`); its wrangler history is `v1` create → `v2` `CronTasksWorker` → `v3` `deleted_classes`.
- `scheduled/` — `DatabaseCleanupTask` (draft/orphan apps, sessions, credentials, tombstones, empty users) extending the kit's `AbstractScheduledTask` (`@rexezuge/runtime`); it returns a `TaskRunSummary` and records no run rows (`getTaskType()` stays `null` — there is no task-runs table).

**Packages**:

- `shared/` — cross-package constants, models, schemas, utils (`BaseUrlUtil`, `CalDavCredentialUtil`, `RetryAfterError`).
- `backend-runtime/` — `ConfigurationManager` (static namespace; add new env vars via namespace groups, not inline — `EnvParser` is the kit's); `http/` response helpers (`jsonResponse`, `errorResponse` mapping a `ServiceError` → `{ error }`); DO naming constants.
- `backend-data/` — all D1 access via DAOs (`ConnectedApplicationDAO`, `CalDavCredentialDAO`, `CalendarObjectMappingDAO`, `OAuth2AuthorizationSessionDAO`, `UserDAO`, `UserEmailDAO`) on the kit's `BaseDAO` and the repo's `EncryptedDAO`; the identity DAOs are the kit's (`UserDAO` subclasses it with only the retention `touch`/`deleteInactiveEmptyBefore`, `UserEmailDAO` is a re-export); utils `D1SessionUtil` (`createD1SessionEnv`).
- `provider-clients/` — `calendar/` (`CalendarProviderUtil` facade dispatching on provider id + `GoogleCalendarProviderUtil`/`OutlookCalendarProviderUtil` + shared HTTP/retry in `BaseCalendarHttp`), `oauth2/` (`OAuth2ProviderUtil`). New provider behavior → per-provider util behind the facade, not branch on provider id in callers.
- `backend-services/` — business logic by domain: `application/` (`ApplicationService`), `calendar/` (`CalendarService`, `CalDavUtil`, `ICalendarUtil`), `credential/` (`CredentialService`), `oauth2/` (`OAuth2AuthorizationService`, `OAuth2AccessTokenService` — PKCE/state via the kit's `generateState`/`generateCodeVerifier`/`getCodeChallenge`/`getStateHash` from `@rexezuge/shared`), `user/` (`UserService` — account resolution is the kit's `UserIdentityService` from `@rexezuge/identity`, called here with the repo's heartbeat). There is no `auth/` package: Access authentication is the kit's `authenticateAccess`, called from the API middleware.

**Other**: `migrations/` (latest: `0006_converge_user_identity.sql`), `functions/[[path]].ts` (Pages → API Worker proxy, via the kit's `createPagesProxy()`), `test/` (Vitest suites: `dao/`, `helpers/`, `middleware/`, `ops/`, `schema/`, `security/`, `services/`, `tasks/`, `utils/`, `web/`, `workers/`), `test/integration/` (its own config: worker + real DAOs against `node:sqlite` with the migrations applied). Aliases, coverage rules and thresholds live in `vitest.shared.mts`, imported by `vitest.config.mts` and `test/integration/vitest.config.mts`.

## The Kit (`@rexezuge/*`)

The framework kernel is **not in this repo**. It lives in `Rexezuge-CloudflareWorkers/SDK` and is consumed as a normal dependency:

| Kit package | Replaces what this repo used to carry |
| --- | --- |
| `@rexezuge/errors` | the whole `backend-errors` package |
| `@rexezuge/runtime` | `backend-runtime/base/*`, `EnvParser`; `apps/background/scheduled/IScheduledTask` (now `AbstractScheduledTask`) |
| `@rexezuge/shared` | `shared/utils/{CryptoUtil,TimestampUtil,UUIDUtil}.ts`; `backend-services/oauth2/OAuth2StateUtil` (now `generateState`/`generateCodeVerifier`/`getCodeChallenge`/`getStateHash`) |
| `@rexezuge/d1` | `backend-data/{dao/BaseDAO, utils/D1Utils, utils/D1ErrorClassifier, crypto/aes-gcm}` |
| `@rexezuge/identity` | `backend-services/user/UserIdentityService` and the identity SQL in `backend-data/dao/{UserDAO,UserEmailDAO}` (now a retention subclass + a re-export) |
| `@rexezuge/http` | `backend-services/auth/EmailValidationUtil` (now `authenticateAccess` in the API middleware) |
| `@rexezuge/web` | `apps/web` converged primitives: `ModalShell`, `EmptyState`, `NoticeBar`/`useNotice`, `Unauthorized`, `ReadOnlyField`/`useCopyToClipboard`, `NOTICE_TIMEOUT_MS`/`COPY_FEEDBACK_TIMEOUT_MS` |
| `@rexezuge/tooling` | `functions/[[path]].ts` (now `createPagesProxy()`), the `spa-shell-embed` plugin in `apps/web/vite.config.ts` (now `spaShellEmbedPlugin`) |

Kit APIs this repo has adapted to:

- **Errors** are the kit taxonomy: `error.status` / `error.type` / `error.retryable` / `error.expose` / `ServiceError.from(value)` — there are no `getErrorCode()`/`getErrorMessage()` getters. The kit carries no transport headers, so the one case that needs one throws `RetryAfterError` (in `shared/`), and `errorResponse`/`safeDav` read `error.headers` off that class only.
- **BaseDAO is sql-first**: `run(sql, bindings)`, `first<T>(sql, bindings)` (absence is `null`, matching `D1Result.first()` — repo DAOs normalize to `undefined` at their own boundary with `?? undefined`), `all<T>(sql, bindings)`, `count`, `batch(statements)`. DAOs state their SQL directly; there is no closure wrapper.
- **AES-GCM** is `encryptSecret(plaintext, key)` / `decryptSecret({ ciphertext, iv }, key)` with the kit's envelope, and the key must be **base64 of exactly 32 bytes** (`AES_ENCRYPTION_KEY`), enforced fail-closed.
- **Identity is `@rexezuge/identity`**: `ResolvedAccount = { id, email, anchorEmail, username }`; `resolveOrRegister(email)` returns `null` when the registry says an address belongs to an account that cannot be materialized, which `UserService` surfaces as a 500 rather than handing out an identity that owns nothing.
- `PayloadTooLargeError` is the 413 class name.

**Dependency wiring.** The kit deps are ordinary published versions (exact `1.9.1`, not ranges), so CI is a plain `pnpm install` — no kit staging and no relink script. All `@rexezuge/*` deps move together, root devDependencies included. A lockfile that resolves one package at one version and another at the next loads *two copies* of the taxonomy, and `error instanceof ServiceError` then answers false across the boundary — the service suites fail in ways that look like logic bugs and are not. To test against a local SDK checkout deliberately, repoint the declarations in every `package.json` that carries them (there are several), install, and restore the pins before committing.

**Vitest resolves the kit differently.** Vitest 4 would externalize the kit's `dist/` and hand it to Node's ESM resolver; `vitest.shared.mts` instead lists the kit in `resolve.noExternal` via the kit's own `KIT_NO_EXTERNAL` constant (`@rexezuge/tooling/vitest`), so the kit runs through Vite's pipeline — the same resolver that bundles the worker and the SPA — and a test loads the very dist the worker ships. Using the kit's constant keeps a consumer's rule and the kit's factories from drifting apart.

**Identity is the kit's now** — see **User Identity** below.

Deliberately **not** adopted (consumer-side decisions, re-evaluate per kit release):

- `@rexezuge/http` `ErrorMapper`/`toErrorResponse`: the kit's envelope is `{ Exception: { Type, Message } }`; `/user/*` answers `{ error }` and the DAV surface answers XML. A surface with its own dialect keeps it (the kit's own rule) — the local `errorResponse`/`safeDav` stay, normalizing through `ServiceError.from`. Same reason `rateLimit`/`securityHeaders`/`routeBase` are not adopted: no local equivalent exists, so that would be behavior change, not dedup.
- `@rexezuge/web` `Button`/`Card`/`Badge`/`Input` (kit excludes them from its own codemod table — its versions restyle), `createApiClient`/`useCurrentUser` (envelope-coupled to `{ Exception }`; this backend speaks `{ error }`), `useSpaLanguage`/`LanguageSelector` (no locale system here), `AppPage`/`PageHeaderCard`/`ContextBar`/`RefreshButton`/`TypeToConfirmModal` (no local equivalent). Local `ConfirmDeleteModal` stays as a domain composition (icon + danger styling the kit's generic one has no slot for) but now sits on the kit's `ModalShell`.
- `@rexezuge/tooling` config factories: `defineRepoLintConfig` (its canonical `apps/api` layer bans the `backend-data` value imports the DAV worker deliberately uses), `defineUnitVitestConfig`/`defineWebVitestConfig` (no workspace-alias options for this repo's alias shape, `web-*` naming assumption, hardcoded jsdom while this repo runs happy-dom). Adopted from tooling: `createPagesProxy`, `spaShellEmbedPlugin`, `KIT_NO_EXTERNAL`.

## CI

`.github/` — `actions/setup-env` (pnpm + Node 24 + cached install) and `actions/retry-step` (re-runs a bash command on failure; every wrangler and `gh` call goes through it, since those are the flaky ones). `workflows/`: `continuous-integration.yml` runs `checks` / `unit-tests` / `integration-tests` / `build` in parallel on `main` and PRs, then auto-merges Dependabot PRs and dispatches deployment after an upstream sync; `continuous-deployment.yml` deploys the Worker and Pages only once CI succeeded on `main`; `backup-main.yml` mirrors `main` to Azure DevOps and GitLab, each gated on its secrets being configured; `scheduled-version-update.yml` stamps `.github/.version`; `upstream-sync.yml` merges upstream `main` into a fork.

`scripts/check-god-files.mjs` reports source files over 300/400 lines. It is **advisory** and always exits 0 -- four files are still over the hard limit, so a gate would fail every push until they are split.

## User Identity

Account identity is `users.id` — `usr_<32 hex>` for accounts created now, v4 UUIDs for rows migration 0004 minted. An email address is _not_ an identity.

- `users.id` — the stable account key. Everything the account owns is keyed on it: `connected_applications.user_id`, and through `application_id`, every CalDAV credential, calendar mapping and OAuth2 session.
- `users.current_email` — the mutable sign-in address, lowercased and unique.
- `users.email` — the **frozen anchor**. Still the PRIMARY KEY, and **never updated**, because `connected_applications` carries a live `FOREIGN KEY (user_email) REFERENCES users(email) ON DELETE CASCADE`. Do not `UPDATE users SET email`. Migration 0004 kept it precisely so that reference could keep resolving without a table rebuild, which D1 does not permit (it honours neither `PRAGMA foreign_keys = off` nor `legacy_alter_table`). Migration 0006 then renamed `user_id` to `id`; SQLite rewrites the child foreign key clauses with the rename, so both references resolve against the migrated schema.
- `users.username` — nullable handle column from the canonical schema; no feature writes it yet.
- `user_emails` — the address registry. `is_verified = 1` means the address may sign in; a changed-away-from address is retained with `is_verified = 0` so pre-change rows stay attributable, and is re-pointed (never deleted) when a later account legitimately claims it.

Resolution is `@rexezuge/identity`'s `UserIdentityService.resolveOrRegister()` (called from `UserService.upsertUser`, one instance per request) and is ordered deliberately: a registered address is authoritative, and a _revoked_ one re-registers as a fresh account while skipping the `users` anchor fallback — otherwise a reassigned address would hand the previous holder's applications to whoever presents it next. The kit's DAO writes the account; this repo's `UserDAO.touch` adds the retention heartbeat on the login path, because the kit never writes `updated_at` on a resolve.

New accounts prefer the real address as their anchor (matching pre-0004 rows) and fall back to the kit's `newAnchor()` (`anchor-<32 hex>@users.invalid`, an RFC 6761 non-deliverable domain) only when the address is already another account's anchor. `UserDAO.createUser()` reports whether it actually created the row; reading the anchor back instead would return the previous holder's account.

Changing a user's address is an operator action — `pnpm exec tsx scripts/change-email.ts --db caldav-bridge-db --account <email> --to <new> --dry-run` (`--id`, `--remote`, `--audit`). It claims, moves, then revokes, in that order, and never touches the anchor. There is no self-service route: nothing here can prove control of a new address.

## Import Direction

```
Layer 0: shared                          — zero @caldav-bridge/* deps
Layer 1: backend-runtime                 → layer 0 only
Layer 2: backend-data, provider-clients  → layer 0 only
Layer 3: backend-services                → layers 0–2 (not apps)
Layer 5: apps/background                 → layers 0–3 (provider-clients OK)
         apps/api                        → layers 0–3 + background (NOT provider-clients directly)
```

Enforced by ESLint `no-restricted-imports` in `eslint.config.mjs`. The rules ban `@caldav-bridge/*` specifiers only, so `@rexezuge/*` imports are unrestricted by design: the kit is the shared kernel every layer may stand on (this is how `provider-clients` reaches `RetryAfterError` through `shared`, and how `backend-data` imports the kit's `BaseDAO`).

## Auth And Routing

- `/user/*` — Cloudflare Access (`MiddlewareHandlers.userAuthentication()` verifies the `cf-access-jwt-assertion` header), resolves the address to an account via `UserService.upsertUser`, and sets `AuthenticatedUser` (`ResolvedAccount`). Handlers authorize on `id`; `email` is for display only. See **User Identity**.
- `DEV_AUTH_EMAIL` bypasses Access locally.
- `/api/oauth2/callback/:applicationId` — public; secured by one-time state + PKCE.
- `/dav/*` — public to Cloudflare Access; CalDAV Basic auth with generated CalDAV app passwords (`WWW-Authenticate: Basic` challenge on 401).
- `/user/*` requests participate in D1 sessions (`x-d1-bookmark` round-trip for read-after-write consistency); the web `apiFetch` already sends/stores the bookmark.
